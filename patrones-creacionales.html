Patrones creacionales

Resuelven un mismo problema de fondo: cómo crear objetos sin que el código quede pegado a clases concretas.

01Factory Method 02Abstract Factory 03Builder 04Prototype 05Singleton
01

Factory Method

Úsalo cuando: una clase base necesita crear objetos, pero quieres que sus subclases decidan qué tipo exacto crear.

El problema

Tu clase Nivel genera enemigos con new Goblin() directamente. Al agregar "NivelDesierto" con otro enemigo, terminas copiando toda la clase solo para cambiar esa línea.

La solución

La clase base declara un método "crear enemigo" sin implementarlo. Cada subclase de nivel lo sobreescribe con su propio enemigo.

nivel.js 
class Nivel {
  crearEnemigo() {
    throw new Error("Las subclases deben implementar esto");
  }
  poblar() {
    return [this.crearEnemigo(), this.crearEnemigo()];
  }
}

class NivelDesierto extends Nivel {
  crearEnemigo() { return new Escorpion(); }
}

class NivelBosque extends Nivel {
  crearEnemigo() { return new Goblin(); }
}
Diferencia con Factory simpleUna función fábrica normal centraliza el switch; Factory Method lo reparte entre subclases especializadas.
En UnityÚtil en clases base de "generador de oleadas" por bioma.
02

Abstract Factory

Úsalo cuando: necesitas crear familias completas de objetos relacionados, y no pueden mezclarse entre familias.

El problema

Tu juego tiene temas visuales (Medieval, SciFi). Cada uno necesita su propio botón, fondo e ícono. Si el código arma la UI pieza por pieza, es fácil mezclar un botón medieval con un fondo de SciFi por error.

La solución

Una fábrica por tema produce las tres piezas juntas, garantizando que siempre combinen entre sí.

fabricasUI.js 
const fabricaMedieval = {
  crearBoton: () => new BotonMedieval(),
  crearFondo:  () => new FondoMedieval(),
  crearIcono:  () => new IconoMedieval(),
};

const fabricaSciFi = {
  crearBoton: () => new BotonSciFi(),
  crearFondo:  () => new FondoSciFi(),
  crearIcono:  () => new IconoSciFi(),
};

// El menú solo pide "la fábrica del tema actual", nunca mezcla:
function armarMenu(fabrica) {
  return [fabrica.crearFondo(), fabrica.crearBoton(), fabrica.crearIcono()];
}
Diferencia con Factory MethodFactory Method crea un tipo de objeto; Abstract Factory crea una familia completa y coherente.
Ejemplo típicoSkins/temas completos, o assets por plataforma (PC vs. móvil).
03

Builder

Úsalo cuando: un objeto se arma con muchos parámetros opcionales y el constructor se vuelve ilegible.

El problema

Un personaje tiene armadura, arma, mascota, título y habilidades — todos opcionales. Un constructor de 8 parámetros posicionales es imposible de leer y fácil de usar en el orden equivocado.

La solución

Un objeto "constructor" arma la pieza por pieza, con nombres claros, y entrega el resultado al final.

personajeBuilder.js 
class PersonajeBuilder {
  constructor() { this.personaje = { habilidades: [] }; }

  conArma(arma)       { this.personaje.arma = arma; return this; }
  conArmadura(a)      { this.personaje.armadura = a; return this; }
  conHabilidad(h)     { this.personaje.habilidades.push(h); return this; }
  construir()         { return this.personaje; }
}

const heroe = new PersonajeBuilder()
  .conArma("espada")
  .conArmadura("cuero")
  .conHabilidad("parada")
  .construir();
BeneficioSe lee como una receta y solo configuras lo que necesitas, en el orden que quieras.
En UnityMuy usado para configurar ScriptableObject complejos o diálogos con muchas opciones.
04

Prototype

Úsalo cuando: crear un objeto desde cero es costoso o repetitivo, pero ya tienes uno parecido.

El problema

Crear un enemigo "Elite" implica copiar a mano 20 propiedades de un enemigo base y ajustar solo 2. Es fácil olvidar una propiedad y que el Elite quede mal configurado.

La solución

El objeto sabe clonarse a sí mismo completo. Luego solo ajustas las diferencias sobre la copia.

enemigo.js 
class Enemigo {
  constructor(datos) { Object.assign(this, datos); }

  clonar() {
    return new Enemigo({ ...this }); // copia todas las propiedades actuales
  }
}

const goblinBase = new Enemigo({ vida: 30, daño: 5, velocidad: 2 });

const goblinElite = goblinBase.clonar();
goblinElite.vida *= 3;
goblinElite.esElite = true;
BeneficioNunca olvidas una propiedad porque la copia siempre es completa.
En UnityMuy cercano a lo que hace Instantiate() sobre un prefab: clonas una plantilla ya armada.
05

Singleton

Úsalo cuando: necesitas exactamente una instancia de algo, accesible desde cualquier parte del código.

El problema

Tu GameManager guarda el puntaje y el estado de la partida. Varios scripts crean su propia instancia por accidente y el puntaje se descuadra entre "instancias fantasma".

La solución

Una clase controla su propia instancia única y la expone globalmente. Nadie más puede crear otra.

gameManager.js 
class GameManager {
  static #instancia;

  constructor() {
    if (GameManager.#instancia) {
      throw new Error("Usa GameManager.obtener(), no 'new'");
    }
    this.puntaje = 0;
  }

  static obtener() {
    if (!GameManager.#instancia) {
      GameManager.#instancia = new GameManager();
    }
    return GameManager.#instancia;
  }
}

// En cualquier archivo:
GameManager.obtener().puntaje += 10;
RiesgoAbusarlo convierte el código en variables globales disfrazadas. Resérvalo para managers reales (audio, guardado, escenas).
En UnityMismo patrón con DontDestroyOnLoad para que sobreviva entre escenas.
