Patrones de comportamiento (II)

Más formas de repartir responsabilidades y hacer intercambiables los algoritmos entre objetos.

01Observer 02State 03Strategy 04Template Method 05Visitor
01

Observer

Úsalo cuando: varios sistemas deben reaccionar a un evento sin conocerse entre sí.

El problema

Cuando el jugador pierde vida, hay que actualizar la UI, reproducir sonido y revisar si murió. El componente Vida termina llamando directamente a los otros tres, acoplando todo.

La solución

Vida solo anuncia "cambié", sin saber quién escucha. Cada sistema se suscribe por su cuenta.

vida.js 
class Vida {
  constructor() {
    this.valor = 100;
    this.escuchas = [];
  }

  alRecibirDaño(cb) { this.escuchas.push(cb); }

  recibirDaño(cantidad) {
    this.valor -= cantidad;
    this.escuchas.forEach(cb => cb(this.valor));
  }
}

// Cada sistema se suscribe sin que Vida lo sepa:
vida.alRecibirDaño(v => ui.actualizarBarra(v));
vida.alRecibirDaño(v => audio.reproducir("golpe"));
vida.alRecibirDaño(v => { if (v <= 0) juego.terminar(); });
Ya lo usasaddEventListener en JS y UnityEvent/Action en Unity son Observer.
RiesgoSi nadie se "desuscribe", puedes acumular escuchas fantasma (memory leak).
02

State

Úsalo cuando: el comportamiento de un objeto cambia según una condición interna, y los if/else se multiplican.

El problema

El personaje tiene if (estado === "idle") ... else if (estado === "corriendo") ... else if (estado === "saltando")... repetido en Update, en animación y en input. Cada estado nuevo multiplica el desorden.

La solución

Cada estado es un objeto con su propio comportamiento. El personaje solo delega al estado actual.

estados.js 
const EstadoIdle = {
  actualizar(personaje) {
    if (personaje.input.moviendose) personaje.cambiarEstado(EstadoCorrer);
  }
};

const EstadoCorrer = {
  actualizar(personaje) {
    personaje.mover();
    if (personaje.input.salto) personaje.cambiarEstado(EstadoSaltar);
  }
};

// El personaje no sabe qué estado es, solo delega:
personaje.estadoActual.actualizar(personaje);
BeneficioAñadir "Agacharse" es crear un objeto nuevo, no editar los existentes.
En UnityLos Animator Controllers son esencialmente máquinas de estado visuales de este mismo patrón.
03

Strategy

Úsalo cuando: necesitas intercambiar un algoritmo en tiempo real sin duplicar el resto del código.

El problema

Tres tipos de enemigos comparten el 90% del código (moverse, atacar, morir), pero cada uno decide diferente a quién perseguir. Terminas con tres clases casi idénticas copiadas y pegadas.

La solución

La clase base es una sola. El "cómo perseguir" se le inyecta como una pieza intercambiable.

enemigo.js 
const perseguirDeCerca = objetivo => objetivo.posicion;
const perseguirADistancia = objetivo => objetivo.posicion.alejar(5);

class Enemigo {
  constructor(estrategiaPersecucion) {
    this.perseguir = estrategiaPersecucion; // la pieza intercambiable
  }

  actualizar(jugador) {
    const destino = this.perseguir(jugador);
    this.moverHacia(destino);
  }
}

const goblin  = new Enemigo(perseguirDeCerca);
const arquero = new Enemigo(perseguirADistancia);
Diferencia con StateState cambia solo, según condiciones internas. Strategy lo eliges tú al crear el objeto (o lo cambias por reglas externas).
En UnityÚtil para IA: inyectar distintos comportamientos sin heredar de clases distintas.
04

Template Method

Úsalo cuando: varias clases siguen los mismos pasos, en el mismo orden, pero uno o dos pasos cambian según el caso.

El problema

"Cargar nivel" siempre sigue 4 pasos: leer archivo, instanciar objetos, colocar al jugador, iniciar cámara. Cada tipo de nivel cambia solo el paso 2, pero terminas copiando los 4 pasos completos en cada clase.

La solución

Una clase base fija el orden de los 4 pasos. Las subclases solo sobreescriben el paso que realmente cambia.

cargadorNivel.js 
class CargadorNivel {
  cargar() { // el orden fijo, el "template"
    this.leerArchivo();
    this.instanciarObjetos(); // paso que varía
    this.colocarJugador();
    this.iniciarCamara();
  }
  leerArchivo()       { /* igual para todos */ }
  colocarJugador()    { /* igual para todos */ }
  iniciarCamara()     { /* igual para todos */ }
}

class NivelJefe extends CargadorNivel {
  instanciarObjetos() { spawnJefeConIntro(); } // solo esto cambia
}
Diferencia con StrategyStrategy reemplaza un algoritmo completo desde afuera; Template Method fija la mayoría de los pasos y solo permite variar algunos, desde adentro (herencia).
En UnityLos métodos Awake/Start/Update de MonoBehaviour siguen esta misma idea: Unity fija cuándo se llaman, tú rellenas el contenido.
05

Visitor

Úsalo cuando: necesitas agregar una operación nueva a un grupo de clases ya existentes, sin modificarlas ni arriesgar romperlas.

El problema

Tienes 8 tipos de objetos del mapa (árbol, roca, cofre...) y necesitas agregar "calcular sombra proyectada" a todos ellos, pero modificar cada una de las 8 clases arriesga romper código que ya funciona.

La solución

Un objeto "visitante" contiene la nueva operación y sabe cómo aplicarse a cada tipo. Las clases originales solo necesitan aceptar la visita.

visitanteSombra.js 
class Arbol {
  aceptar(visitante) { visitante.visitarArbol(this); }
}
class Roca {
  aceptar(visitante) { visitante.visitarRoca(this); }
}

const visitanteSombra = {
  visitarArbol(a) { return a.altura * 1.5; },
  visitarRoca(r)  { return r.radio * 0.8; },
};

// Cada objeto del mapa acepta al mismo visitante, sin conocerlo antes:
objetosDelMapa.forEach(o => o.aceptar(visitanteSombra));
BeneficioLa operación nueva vive en un solo archivo, no repartida en 8 clases.
CostoSi agregas un tipo de objeto nuevo, hay que actualizar el visitante — es el patrón más pesado de esta lista, resérvalo para operaciones que realmente cruzan muchos tipos.
