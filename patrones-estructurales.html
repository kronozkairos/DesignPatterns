Patrones estructurales

Resuelven cómo combinar clases y objetos en estructuras más grandes, manteniéndolas flexibles y eficientes.

01Adapter 02Bridge 03Composite 04Decorator 05Facade 06Flyweight 07Proxy
01

Adapter

Úsalo cuando: necesitas conectar dos piezas de código cuyas interfaces no coinciden.

El problema

Integras una librería de sonido externa cuyo método se llama playFX(id), pero todo tu código ya está escrito esperando reproducir(nombre). Reescribir todo tu código es innecesario.

La solución

Una clase intermedia envuelve la librería externa y traduce las llamadas a la interfaz que tu código espera.

adaptadorAudio.js 
class AdaptadorAudio {
  constructor(libreriaExterna) { this.lib = libreriaExterna; }

  reproducir(nombre) {
    const id = mapearNombreAId(nombre); // traduce el vocabulario
    this.lib.playFX(id);
  }
}

// El resto del juego nunca sabe que existe la librería externa:
const audio = new AdaptadorAudio(libreriaTerceros);
audio.reproducir("explosion");
BeneficioSi cambias de librería de audio, solo reescribes el adaptador.
En UnityFrecuente al integrar SDKs de terceros (anuncios, analíticas, tiendas).
02

Bridge

Úsalo cuando: tienes dos ejes de variación (por ejemplo "qué es" y "cómo se muestra") y combinarlos en una sola jerarquía de clases explota.

El problema

Tienes formas (Círculo, Cuadrado) que deben renderizarse en distintos motores gráficos (2D, 3D). Una clase por cada combinación (CírculoRender2D, CírculoRender3D, CuadradoRender2D...) crece sin control.

La solución

La forma no hereda del renderer: lo recibe como una pieza separada e intercambiable, un "puente" entre los dos ejes.

forma.js 
class Forma {
  constructor(renderer) { this.renderer = renderer; } // el "puente"
  dibujar() { this.renderer.dibujarForma(this); }
}

class Circulo extends Forma { }
class Cuadrado extends Forma { }

// Cualquier forma + cualquier renderer, sin multiplicar clases:
const circulo3D = new Circulo(renderer3D);
const cuadrado2D = new Cuadrado(renderer2D);
Diferencia con AdapterAdapter conecta interfaces ya existentes que no coinciden; Bridge se diseña desde el inicio para separar dos ejes que van a variar.
Ejemplo típicoSeparar la lógica de un control (teclado, gamepad, táctil) de la acción que dispara.
03

Composite

Úsalo cuando: necesitas tratar un objeto individual y un grupo de esos objetos exactamente igual.

El problema

Un inventario tiene ítems sueltos y también "bolsas" que contienen otros ítems (incluso otras bolsas). Calcular el peso total requiere código distinto para cada caso, con recursión manual regada por todos lados.

La solución

Ítem y bolsa implementan la misma interfaz. La bolsa simplemente suma el peso de lo que contiene, sin que el resto del código note la diferencia.

inventario.js 
class Item {
  constructor(peso) { this.peso = peso; }
  obtenerPeso() { return this.peso; }
}

class Bolsa {
  constructor() { this.contenido = []; }
  agregar(item) { this.contenido.push(item); }
  obtenerPeso() {
    return this.contenido.reduce((suma, i) => suma + i.obtenerPeso(), 0);
  }
}

const mochila = new Bolsa();
mochila.agregar(new Item(2));
mochila.agregar(new Bolsa()); // una bolsa dentro de otra, sin problema
BeneficioEl código que pide "el peso" nunca pregunta si es un ítem o una bolsa.
En UnityEs la misma idea detrás de la jerarquía de Transform: un padre y sus hijos se tratan de forma uniforme.
04

Decorator

Úsalo cuando: quieres añadir comportamiento a un objeto de forma dinámica, sin tocar su clase ni crear una subclase por combinación.

El problema

Un arma puede tener fuego, veneno, o ambos combinados. Crear una subclase por cada combinación (ArmaFuego, ArmaVeneno, ArmaFuegoVeneno...) crece exponencialmente con cada efecto nuevo.

La solución

Cada efecto envuelve al arma original y añade su parte del daño, sin tocar la clase base. Se pueden apilar libremente.

armaDecorada.js 
class ArmaBase {
  calcularDaño() { return 10; }
}

class ConFuego {
  constructor(arma) { this.arma = arma; }
  calcularDaño() { return this.arma.calcularDaño() + 5; }
}

class ConVeneno {
  constructor(arma) { this.arma = arma; }
  calcularDaño() { return this.arma.calcularDaño() + 3; }
}

// Se combinan envolviendo, sin crear ninguna clase nueva:
const espadaLegendaria = new ConVeneno(new ConFuego(new ArmaBase()));
BeneficioN efectos combinables sin N² subclases.
En UnitySimilar en espíritu a apilar varios Component sobre el mismo GameObject.
05

Facade

Úsalo cuando: un sistema complejo de varias piezas necesita un punto de entrada simple.

El problema

Iniciar una partida requiere llamar en orden a 6 subsistemas (audio, red, guardado, UI, física, cámara). Cada script que arranca el juego repite esas 6 llamadas, y si cambia el orden hay que actualizarlas todas.

La solución

Una única clase ofrece un método simple que oculta y coordina toda esa complejidad internamente.

juegoFacade.js 
class Juego {
  static iniciar() {
    Audio.precargar();
    Red.conectar();
    Guardado.cargarProgreso();
    UI.mostrarHUD();
    Fisica.activar();
    Camara.enfocarJugador();
  }
}

// Cualquier script solo necesita esto:
Juego.iniciar();
BeneficioEl orden y los detalles viven en un solo lugar, no repetidos por todo el proyecto.
NotaNo reemplaza a los subsistemas, solo simplifica cómo se usan juntos desde afuera.
06

Flyweight

Úsalo cuando: tienes muchísimos objetos similares y duplicar sus datos comunes desperdicia memoria.

El problema

Un bosque con 10,000 árboles; si cada instancia guarda su propio modelo 3D y textura, estás duplicando los mismos datos pesados 10,000 veces en memoria.

La solución

El modelo y la textura se guardan una sola vez y se comparten. Cada árbol solo guarda lo que sí es único: su posición y escala.

bosque.js 
// Datos pesados y compartidos: se cargan UNA sola vez
const modeloArbolCompartido = { malla: cargarMalla(), textura: cargarTextura() };

// Cada árbol solo guarda lo que cambia de instancia a instancia
class ArbolInstancia {
  constructor(x, y, escala) {
    this.x = x; this.y = y; this.escala = escala;
    this.modelo = modeloArbolCompartido; // referencia, no copia
  }
}
BeneficioMemoria proporcional a los árboles únicos, no a las 10,000 copias.
En UnityEs la razón de ser de GPU Instancing y los sistemas de partículas: un modelo, miles de instancias baratas.
07

Proxy

Úsalo cuando: quieres controlar o retrasar el acceso a un objeto costoso, sin que quien lo usa note la diferencia.

El problema

Cargar una textura de 4K es lento. Si la cargas cada vez que el objeto aparece en pantalla, el juego se congela un instante en cada aparición.

La solución

Un objeto sustituto (proxy) intercepta las llamadas: carga la textura real solo la primera vez y reutiliza esa copia después.

texturaProxy.js 
class TexturaProxy {
  constructor(ruta) { this.ruta = ruta; this.texturaReal = null; }

  obtener() {
    if (!this.texturaReal) {
      this.texturaReal = cargarTexturaPesada(this.ruta); // solo la primera vez
    }
    return this.texturaReal;
  }
}

// El resto del código lo usa como si fuera la textura real:
const textura = new TexturaProxy("roca_4k.png");
BeneficioCarga perezosa ("lazy loading") transparente para el resto del código.
Otros usosProxy también sirve para permisos de acceso o para registrar (log) cada llamada a un objeto.
