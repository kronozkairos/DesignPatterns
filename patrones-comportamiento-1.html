01

Chain of Responsibility

Úsalo cuando: una solicitud debe pasar por varios manejadores posibles, hasta que uno la resuelva.

El problema

Al recibir daño hay que revisar primero el escudo, luego la armadura, y por último la vida — en ese orden. El código es un bloque gigante de if anidados que crece con cada nueva capa de defensa.

La solución

Cada defensa es un eslabón: absorbe lo que puede y pasa el resto al siguiente eslabón de la cadena.

cadenaDeDaño.js 
class Escudo {
  constructor(siguiente) { this.siguiente = siguiente; this.puntos = 20; }
  recibir(daño) {
    const absorbido = Math.min(daño, this.puntos);
    this.puntos -= absorbido;
    const restante = daño - absorbido;
    if (restante > 0 && this.siguiente) this.siguiente.recibir(restante);
  }
}

// Escudo -> Armadura -> Vida, cada uno solo se preocupa de su parte
const cadena = new Escudo(new Armadura(new Vida()));
cadena.recibir(35);
BeneficioAñadir una defensa nueva es insertar un eslabón, no reescribir un if gigante.
Otro uso comúnValidación de formularios: cada regla revisa el dato y pasa al siguiente validador.
02

Command

Úsalo cuando: necesitas guardar, encolar o deshacer acciones, no solo ejecutarlas al momento.

El problema

Quieres un botón de "deshacer" en tu editor de niveles, pero cada acción (mover, borrar, pintar) está escrita como una llamada directa a una función. No hay forma de revertirla después.

La solución

Cada acción se convierte en un objeto con ejecutar() y deshacer(). Se guarda en una pila para poder revertirla.

comandoMover.js 
class ComandoMover {
  constructor(objeto, delta) { this.objeto = objeto; this.delta = delta; }
  ejecutar() { this.objeto.posicion += this.delta; }
  deshacer()  { this.objeto.posicion -= this.delta; }
}

const historial = [];
function ejecutarComando(cmd) { cmd.ejecutar(); historial.push(cmd); }
function deshacerUltimo()      { historial.pop()?.deshacer(); }
BeneficioDeshacer, rehacer y encolar acciones salen "gratis" una vez que son objetos.
Otro usoReasignar controles (input remapping): cada tecla dispara un Comando, no una función fija.
03

Iterator

Úsalo cuando: necesitas recorrer una colección sin que el código que la recorre dependa de cómo está construida por dentro.

El problema

Tu inventario a veces es un array y a veces un árbol de categorías. El código que lo recorre está escrito para arrays y se rompe si cambias la estructura interna.

La solución

La colección expone un recorrido uniforme (siguiente(), hayMas()), sin importar si por dentro es un array, un árbol o una lista enlazada.

inventarioIterador.js 
class Inventario {
  constructor(items) { this.items = items; }

  [Symbol.iterator]() {
    let i = 0;
    const items = this.items;
    return {
      next: () => i < items.length
        ? { value: items[i++], done: false }
        : { value: undefined, done: true }
    };
  }
}

// El código cliente no sabe (ni le importa) cómo se guardan los items:
for (const item of new Inventario(misItems)) { mostrar(item); }
Ya lo usasEl for...of de JS y foreach de C# existen gracias a este patrón.
BeneficioCambiar la estructura interna de la colección no obliga a tocar el código que la recorre.
04

Mediator

Úsalo cuando: varios objetos se comunican directamente entre sí, formando una maraña de referencias cruzadas.

El problema

En un formulario de configuración, el checkbox llama al dropdown, el dropdown llama al botón, el botón llama de vuelta al checkbox. Cada campo nuevo obliga a conectar referencias con todos los demás.

La solución

Un mediador recibe los eventos de cada campo y decide cómo reaccionan los demás. Los campos ya no se conocen entre sí.

mediadorFormulario.js 
class MediadorFormulario {
  notificar(origen, evento) {
    if (origen === "checkboxAvanzado" && evento === "activado") {
      this.dropdown.habilitar();
      this.boton.deshabilitar();
    }
  }
}

// Cada campo solo conoce al mediador, nunca a los demás campos:
checkbox.alCambiar = () => mediador.notificar("checkboxAvanzado", "activado");
BeneficioAgregar un campo nuevo significa enseñarle al mediador, no editar N campos existentes.
Diferencia con ObserverObserver es un anuncio abierto a quien quiera escuchar; Mediator centraliza la lógica de "quién reacciona a qué" en un solo lugar.
05

Memento

Úsalo cuando: necesitas guardar y restaurar el estado anterior de un objeto sin exponer sus datos internos al resto del código.

El problema

Quieres un "guardado rápido" (quicksave), pero el estado del jugador tiene campos que deberían ser privados. Exponerlos todos para poder guardarlos rompe el encapsulamiento de la clase.

La solución

El propio objeto genera una "foto" (memento) de sí mismo. Un gestor externo la guarda sin mirar adentro, y luego se la devuelve al objeto para restaurarse.

jugadorMemento.js 
class Jugador {
  constructor() { this.vida = 100; this.posicion = { x: 0, y: 0 }; }

  guardar() {
    return { vida: this.vida, posicion: { ...this.posicion } }; // el "memento"
  }

  restaurar(memento) {
    this.vida = memento.vida;
    this.posicion = memento.posicion;
  }
}

const checkpoint = jugador.guardar();
// ...el jugador muere o algo sale mal...
jugador.restaurar(checkpoint);
BeneficioEl sistema de guardado no necesita entender la estructura interna del jugador.
En UnityBase conceptual de cualquier sistema de checkpoints o guardado en JSON.
